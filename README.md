# 和田歯科医院 経理突合システム

レシート・カード明細の突合を Google Apps Script（スプレッドシート）で行う。
AI/OCR は **候補を出すだけ** で、経理担当者の承認なしに取引を確定・計上しない。

| `v8/` | V8（新スプレッドシートで動かす新規開発。V7と混在させない） | 実装済み・Google環境での受入テスト待ち |

## V8

### セットアップ

1. 新しいスプレッドシートを作成（V7専用スプレッドシートは使わない。V7のタブがあると V8 は起動を拒否する）
2. 拡張機能 → Apps Script を開き、`コード.gs` の中身を全部消して [`dist/V8_all.gs`](dist/V8_all.gs) の全文を貼り付けて保存
   - プロジェクトの設定 → タイムゾーンを「(GMT+09:00) 東京」にする
   - 分割ファイルのまま入れたい場合は `v8/` の `.gs` 9ファイルと `appsscript.json`（clasp なら `rootDir` を `v8` にして push）
   - `v8/` を修正したら `npm run build` で `dist/V8_all.gs` を作り直す
3. スプレッドシートを再読込 → メニュー `🦷 突合V8` → `【初回】V8シート作成` → 認可
4. `フォルダマスタ` を確認。V7 のフォルダIDを登録済み
5. 各フォルダの直下に **`2026-09` 形式の月フォルダ** を作り、原本はその中に置く

### 保存規則

`対象月 / 人物 / 支払手段 / 原本種別` を保存先から一意に判別できない原本は取り込まず `分類要確認` にする。

- 月フォルダの外に置いた・月フォルダ名が読めない → `分類要確認`
- 複数カードが同居する明細フォルダ（院長 `セゾン・DC`、麻記子先生 `楽天・大丸・ポケット・DC`）は、**ファイル名にカード名を入れる**（例 `2026-09_楽天.csv`）。特定できなければ `分類要確認`
- 同じ内容（ハッシュ一致）のファイルは二重取込しない。同じDriveファイルIDで内容を差し替えた場合は処理版を増やし、旧版の取引は削除せず `旧版` にする

### 月次の手順

1. レシートをカード別にスキャンし、該当フォルダの月フォルダへ（一括PDFのままで可）
2. `① レシート読込` — PDFをページ単位でOCR。6分制限に近づいたら中断し、再実行で続きのページから再開
3. カード明細（CSV / xlsx / Googleスプレッドシート）を明細フォルダの月フォルダへ
4. `② カード明細読込` — 取込後に自動で再突合（翌月確認の取引もここで再判定）
5. `要確認一覧`（人物 → カード → 日付順）と `突合結果` で原本を開いて確認
6. `判断` 列で `承認` / `却下` を選び、`判断を反映`
7. OCR誤読は `取引台帳` の `修正_日付/修正_金額/修正_通貨/修正_店舗名/修正理由` に入力し `修正を反映して再突合`

### シート

| シート | 役割 |
| --- | --- |
| 要確認一覧 | 横断の要確認一覧。取引単位の承認/却下（理由メモ必須） |
| 突合結果 | 突合候補の一覧。承認/却下 |
| 取引台帳 | 原本値・修正値・判定。原本値の列は警告付き保護 |
| 突合台帳 | 候補・承認・却下・失効（削除しない） |
| 取込確認 | 原本ファイル台帳（ハッシュ・処理版・ページ進捗・失敗ページ） |
| 判定履歴 | 状態変更・修正・判断をすべて記録 |
| フォルダマスタ / カード明細列マスタ / 設定 | 管理者が編集 |

**先生＋カード別タブ**（フォルダマスタの先生×カードごとに自動作成。1カード1タブ）

| タブ名の例 | 内容 |
| --- | --- |
| `院長_M-AMEX_突合結果` | 1行に **レシート｜明細｜結果** を横並び・日付順。明細だけ（レシートなし）の行、レシートだけ（明細なし）の行も同じタブに出る。ここで承認/却下できる |
| `院長_現金_突合結果` | 現金のレシート（明細側は空欄） |
| `院長_カード不明` | 支払手段「不明」のレシート（同額の明細があるカード・翌月確認・現金の可能性） |

月をまたいでも横に並ぶ: 突合は同じ先生・同じカードの取込済み明細すべてが対象（ファイル・月フォルダで区切らない）。
9/28 のレシートは 9月明細の時点では `翌月確認`、10月にダウンロードした明細に載っていれば取込時に同じ行へ並ぶ。

旧版で作った `_レシート`・`_明細` タブは、見出しが旧版と完全に一致する場合だけ自動で片付ける。

**明細の重複行**: 期間が重なるファイル（例 9/1〜9/30 と 9/15〜10/15）を両方取り込んだ場合、
先生・カード・**利用日・金額**・店名（全角半角を正規化）・外貨額がすべて一致し、**別ファイル**にある行を `重複行` として突合から外す（行は削除しない）。

- 同じ店・同じ月の購入でも、日付か金額が1つでも違えば重複にしない
- 同じ日・同じ店・同じ金額が本当に複数回ある場合は、1ファイル内の件数までを残す
- 残すのは承認・個別判断済みの行 → 先に取り込んだ行の順

**原本区分**: ファイル名に `設定` の「ダウンロード判定キーワード」（初期値: 領収・請求・invoice・receipt・download・ダウンロード・DL_）が入っていれば `ダウンロード（領収書・請求書）`、なければ `紙レシート（スキャン）`。
ダウンロードした領収書・請求書はファイル名に「領収書」「請求書」などを入れて保存する。

`突合結果`・`要確認一覧`・先生＋カード別タブは毎回台帳から作り直す。入力済みで未反映の判断があるときは、作り直しを伴う操作を止める。

### 突合ルール（V8-04）

1. 人物・支払手段が違う明細は候補にしない
2. JPY は円貨額、外貨は明細の外貨額で完全一致
3. 利用日差は `設定` の日付許容日数（初期3日）。カード別は `カード明細列マスタ` で上書き
4. 店舗名は NFKC・小文字化・空白記号除去で比較し、差があれば理由に残す（判定条件には使わない）
5. 候補が一意 → `一致候補`（**未承認**）。複数（1対多・多対1）→ `候補重複`
6. 完全一致がない場合
   - 日付許容内で金額差が検出幅（初期20%）以内 → `金額不一致`
   - 同額で日付差が検出幅（初期45日）以内 → `日付要確認`
   - 外貨で一致する外貨額がない → `外貨要確認`
   - そのカードの取込済み明細の最終日より後 → `翌月確認`（対象翌月を保持）。猶予（初期1か月）を過ぎると `期限超過`
   - それ以外 → `未突合`
7. 現金・返金（マイナス額・取消/分割/引落等）は自動確定の対象外
8. 支払手段 `不明` のレシートは、その人物の全カード明細から同額を探し、見つかれば `分類要確認`（候補カードを表示）、明細未到達のカードがあれば `翌月確認`、全期間で無ければ「現金の可能性」として `未突合`

承認済み・却下の突合は再突合で変わらない。却下したペアは再び候補にしない。

### 1ページ複数レシート

合計金額が2つ以上読めたページは、金額を空欄にして `OCR要確認` にする（自動で選ばない・合算しない）。
`取引を分割` で同じページに取引行を追加し、両方の行に修正値を入れる。

| 仕様 | 実装 |

### Google 環境で最初に確認すること（受入テスト）

Node のテストでは擬似環境を使っているため、以下は実環境で確認が必要:

- メニューから `async` 関数を実行して最後まで動くか（PDF分割に pdf-lib を使うため）
- `cdn.jsdelivr.net` から pdf-lib を取得できるか（`設定` の URL で変更可）
- Drive OCR（`ocrLanguage=ja`）の精度。特に合計金額が別の行に分かれるレシート
- xlsx の Googleスプレッドシート変換
- 受入条件: 10ページPDF・3ページ目だけ失敗・1ページ2枚・OCR修正・候補重複・翌月確認・承認/却下履歴・同一ファイル再取込

### 未確定事項（実データ受領後に対応）

- **カード会社別の実ファイル**（列名・文字コード・前置き行・日付形式）→ `カード明細列マスタ` にカード別の行を追加
- `不明` レシート用フォルダは未作成。作成したら `フォルダマスタ` に行を追加
- 明人先生の分は対象外（仕様どおり）
- V9（現金・外貨・出納帳）、V10（銀行CSV・請求書）、V11（不明明細のAI推測・定期支払い）は未着手
